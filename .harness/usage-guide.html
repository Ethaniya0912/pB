1.아키텍처 — 결정(Skill)과 강제(Hook)의 분리

하네스의 핵심 설계 원칙은 LLM이 따를 절차(결정)와 LLM 판단과 무관하게 항상 일어나야 하는 일(강제)을 분리하는 것이다.

📘 Skill — 무엇을·어떻게 (결정)

unity-pipeline 스킬이 8단계 절차·매트릭스 양식·CLI 템플릿을 안내한다. Claude는 이 절차를 따라 분석·명세·셋업을 수행하고, 게이트에서 멈추고 질문한다.

스킬은 어겨질 수 있다 — 그래서 강제가 따로 있다.

🔒 Hook — 항상 일어나는 일 (강제)

훅은 Claude Code 런타임이 실행한다. 에셋 편집 후 정합화, 파괴적 명령 차단, 체크리스트 미완료 시 종료 차단은 LLM이 잊어도 자동으로 일어난다.

훅은 셸 스크립트라 모델·프롬프트와 무관하게 결정적으로 동작한다.

3-1. jq (권장 — JSON 파싱 정확도)

📍 PowerShell(Win 키 → powershell → Enter)에서 아래 셋 중 하나만 실행:

# Windows — 셋 중 하나 (winget은 Windows 10/11 기본 내장)
winget install jqlang.jq
choco install jq
scoop install jq

📍 확인 — PowerShell 또는 Git Bash 새 창을 열고:

jq --version        # → jq-1.7.x 출력되면 성공

없어도 동작한다(python → sed 폴백). 단, 안전 게이트(guard)의 명령 추출 정확도를 위해 설치 권장.

3-2. unity-cli — CLI 바이너리

📍 PowerShell(Win 키 → powershell → Enter)에 아래 한 줄을 붙여넣고 Enter:

# 공식 인스톨러 — 다운로드와 PATH 등록까지 자동
irm https://raw.githubusercontent.com/youngwoocho02/unity-cli/master/install.ps1 | iex

📍 확인 — PowerShell 또는 Git Bash 새 창을 열고:

unity-cli --version   # → unity-cli v0.2.x 출력되면 성공
unity-cli update      # (이후 아무 때나) 최신으로 업데이트

3-3. unity-cli — Unity Connector 패키지

📍 Unity Editor에서 (Unity Hub → 프로젝트 열기 → 로딩 완료 후):

  1. 최상단 메뉴 바에서 Window → Package Manager 클릭 → Package Manager 창이 뜬다.
  2. 창 왼쪽 위 + 버튼(드롭다운) 클릭 → "Add package from git URL..." 선택.
  3. 입력란에 아래 URL을 붙여넣고 Add 버튼 클릭:
https://github.com/youngwoocho02/unity-cli.git?path=unity-connector
  1. 임포트가 끝나면 목록에 unity-cli-connector가 보이고, Console 창(Window → General → Console)에 에러가 없어야 한다.

대안 — 파일로 직접 추가: 프로젝트 루트의 Packages\manifest.json을 메모장/VS Code로 열고 "dependencies": { 바로 아래에 한 줄 추가(버전 고정은 #v0.2.21 식 태그):

"com.youngwoocho02.unity-cli-connector": "https://github.com/youngwoocho02/unity-cli.git?path=unity-connector",
Connector는 Unity 기동 시 자동 활성화된다(기본 포트 8090, 별도 설정 불필요). 📍 확인: Editor를 켜둔 채 아무 터미널에서 unity-cli --json status → "ready"가 나오면 연결 성공.

3-4. Unity Preferences

📍 Unity Editor 최상단 메뉴 바에서:

  1. Edit → Preferences... 클릭(Mac은 Unity → Settings...) → Preferences 창이 뜬다.
  2. 왼쪽 목록에서 General 탭 선택.
  3. Interaction Mode 드롭다운을 No Throttling으로 변경 → 창 닫기(자동 저장).

효과: Editor가 백그라운드(다른 창에 포커스)일 때도 unity-cli 요청에 즉시 응답한다 — 훅의 컴파일 대기가 짧아진다.

왜 /cycle-start 인가? 폴더 생성이라는 부작용이 있어 모델 자동 호출이 금지돼 있다 (disable-model-invocation: true). 반대로 분석·계획 요청("이 기획서로 개발 계획 세워줘")은 unity-pipeline 스킬이 자동으로 트리거된다 — 단, 사이클 폴더가 없으면 /cycle-start 실행을 먼저 안내한다.

5.게이트 G1~G7 — 응답 방법

게이트에 도달하면 Claude가 자동 진행을 멈추고 결정 요약과 선택지를 제시한다. 사용자는 검토 후 승인·수정·반려를 응답하면 되고, 결정은 decisions.md에 기록된다.

게이트시점무엇을 확인하나강제 주체
G1① 직후기획 해석·모호 항목이 의도와 맞는가Stop 훅
G2③ 직후기존 에셋 수정·영향도 높은 항목 승인Stop 훅
G3④ 직후생성될 파일·경로명 확정(이후 변경 비용 큼)Stop 훅
G4파괴 명령 직전reserialize 대량/Delete/Destroy/rm -rf Assets 등 → 권한 프롬프트(ask/deny)PreToolUse 훅 (자동)
G5⑥ 직후테스트 환경 as-is→to-be 실제 적용 승인Stop 훅
G6테스트 실패 시기계적 수정이 아닌 설계 분기 — 선택지 중 결정수동(스킬 안내)
G7⑧ 직전결과 보고서·diff 검토 후 사이클 사인오프Stop 훅
Stop 훅의 강제 방식: 게이트 대기(awaiting_gate)가 걸린 채, 또는 미체크 task가 남은 채 세션을 끝내려 하면 훅이 종료를 차단하고 사유를 돌려준다 — "사이클 [...] 마감 전 정리 필요 — 미체크 task 3건; 게이트 G2 결정 미기록...". decisions.md 기록·체크리스트 갱신 후에만 정상 종료된다.
G4 권한 프롬프트가 떴을 때: ask는 명령 내용을 읽고 의도한 작업이면 승인. deny(프로젝트 전체 reserialize, Assets 루트 삭제 등)는 자동 차단되며, 범위를 단일 에셋으로 좁히거나 사람이 직접 수행해야 한다.

ask셸 파괴 명령(비-unity-cli)rm -rf Assets|ProjectSettings|Packages|.harness, git clean -f, git reset --hard
allow그 외 전부(무출력)status, console, 읽기 전용 exec, git status

명령 추출이 실패하면 통과시키지 않고 raw 입력으로 패턴을 재검사한다(보수적 안전 게이트).

9.Fail-safe 동작 (미설치 환경)

인프라 부재가 개발 흐름을 죽이지 않도록 모든 훅이 fail-safe로 설계됐다. 안전 게이트(guard)만 예외적으로 보수적이다.

상황동작
unity-cli 미설치load-context: 설치 안내 출력 / post-asset-edit: stderr 경고 후 통과(편집 차단 안 함) / guard: bash grep 패턴 검사는 계속 수행
Editor offline분석 단계(①~⑤)는 계속, 실행 단계(⑥~)는 Editor 기동 요청. 스냅샷은 생략(경고만)
jq 미설치python3 → python → py → sed 순 폴백. guard는 추출 실패 시 raw 입력 검사
unity-cli 무응답(행)ucli 타임아웃 래퍼(기본 50s, compile 120s)가 끊고 비차단 진행
unity-cli 설치 후추가 변경 없이 전 기능 자동 활성화 — 훅이 매 실행마다 command -v unity-cli로 감지

12.주의사항·FAQ

워크트리에서 작업 중인가? 하네스는 브랜치(claude/laughing-gates-da429a → origin/feature/pC/namkyu/harness)에 커밋돼 있다. 메인 프로젝트 폴더(master)에 .harness가 안 보이는 것은 정상 — PR/merge 후 반영된다.
Q. 일반 대화(사이클 무관)도 Stop 훅에 막히나?
A. 아니다. 진행 중 사이클이 없거나 최신 사이클이 완료 상태면 무조건 통과한다.
Q. 사이클을 중도 포기하려면?
A. meta.json의 status를 archived로 바꾸고 _index.md에 한 줄 추가하면 Stop 훅이 통과시킨다. 폴더는 archive/로 이동(포인터 유지).
Q. 이전 사이클 산출물은 어떻게 재사용되나?
A. ③ scope에서 이전 사이클들의 04_assets.md와 최신 snapshots/를 조회해 "이미 구현됨"을 판정한다 — 사이클이 쌓일수록 중복 분석이 줄고 영향도 정확도가 올라간다(누적 설계).
Q. 훅을 일시적으로 끄려면?
A. .claude/settings.json에서 해당 훅 항목을 제거(또는 주석 백업 후 삭제)하고 세션을 재시작한다. 영구 변경은 권장하지 않음 — 강제 계층이 사라진다.
Q. 자주 쓰는 씬 셋업이 반복된다.
A. 프로젝트 C#에 [UnityCliTool]로 승격해 unity-cli tool call <이름>으로 재사용한다(쿡북 §6).
