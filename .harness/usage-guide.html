01

이게 뭔가 — 1분 개요

하네스는 기획→코딩→씬 셋팅→테스트를 unity-cli로 자동화하고, 그 절차를 Claude Code 확장(Skill·Hook·Subagent)으로 구동합니다. 한 기능/보고 단위(=1 사이클)를 9단계로 분석·명세·검증하고, 산출물을 .harness/에 누적합니다.

9단계 파이프라인 — ⑦ plan 이후 task 단위 구현 루프가 돈다

  • Skill = 절차·도메인 지식("무엇을 어떻게"). Hook = 게이트·정합화 강제("항상 일어나야 할 일"). Process = 사이클 누적·색인.
  • 사람의 역할은 "결정·감독" — 되돌리기 어려운 변경(범위 확정·에셋 삭제·환경 적용)은 게이트에서 사람이 승인합니다.
  • 누적이 핵심 — 사이클이 끝나도 용어 사전·증빙·결정 로그가 남아 다음 사이클이 재사용합니다.
02

설치 — 최초 1회 셋업

아래 5단계는 프로젝트당 한 번만. 이미 셋업된 프로젝트(.claude/·.harness/ 존재)라면 1·2·5만 확인하면 됩니다.

1

unity-cli 설치 (CLI 바이너리)

Editor를 명령으로 제어하는 단일 바이너리. MCP·Python 의존성 없음.

Windows — PowerShell
# 설치
irm https://raw.githubusercontent.com/youngwoocho02/unity-cli/master/install.ps1 | iex
Linux / macOS
curl -fsSL https://raw.githubusercontent.com/youngwoocho02/unity-cli/master/install.sh | sh
# 업데이트 (--check 로 확인만)
unity-cli update
2

Unity Connector 패키지 추가

Unity 안에서 CLI 요청을 받는 브릿지. Package Manager → + → Add package from git URL:

git URL
https://github.com/youngwoocho02/unity-cli.git?path=unity-connector

또는 Packages/manifest.json 직접 편집(버전 고정은 #v0.3.22 식 태그). Connector는 Unity 기동 시 자동 활성(기본 포트 8090).

3

Interaction Mode = No Throttling

Edit → Preferences → unity-cli(또는 Interaction Mode) = No Throttling. 백그라운드에서도 명령이 즉시 처리됩니다.

4

하네스 스캐폴딩 — .claude/ + .harness/

Skill·Subagent·Hook·템플릿. 이 가이드가 든 프로젝트는 이미 포함되어 있습니다. 새 프로젝트엔 복사해 둡니다.

  • .claude/skills/unity-pipeline/ — 9단계 절차·템플릿·레퍼런스
  • .claude/skills/cycle-start/ — 사이클 스캐폴딩 진입점
  • .claude/agents/ — asset-auditor · spec-writer · test-runner
  • .harness/ — _conventions.md(규약) · glossary/(용어사전) · hooks/ · cycles/
5

VS Code 확장 + CLAUDE.md

지식 그래프·다이어그램을 보려면 두 확장을 설치(.vscode/extensions.json에 추천됨):

확장무엇
foam.foam-vscode위키링크 [[ ]] 클릭 이동 · 그래프 뷰 · 백링크 패널
bierner.markdown-mermaid마크다운 프리뷰에서 Mermaid 다이어그램 렌더
visualstudiotoolsforunity.vstucUnity C# 편집(IntelliSense)

/init으로 CLAUDE.md를 만들고 프로젝트 구조·컨벤션을 보정합니다(세션마다 자동 로드).

설치 확인

터미널 (Unity Editor 열린 상태)
$ unity-cli status
→ ready · 6000.3.1f1 · Connector 0.3.22 · PID …

ready가 보이면 완료. offline이면 Editor를 열고 Connector 패키지를 확인하세요.

03

첫 사이클 시작

기획·구현·기술 문서를 준비하고, Claude Code 터미널에서 /cycle-start로 시작합니다. 이 한 줄이 사이클 폴더를 만들고 as-is 스냅샷을 떠서 ① target부터 자동 진행합니다.

Claude Code 터미널
/cycle-start docs/기획_인벤토리.md inventory
# → .harness/cycles/2026-06-15_inventory/ 생성 (01~09 템플릿·evidence/·meta.json)
# → snapshots/…_before.txt 에 현재 에셋 목록 덤프 → ① target 분석 시작
  • 입력 문서를 먼저 00_input/에 둘 필요 없음 — cycle-start가 복사합니다. 인자만 주면 됩니다.
  • 슬러그(폴더명 꼬리)는 선택 — 생략하면 파일명에서 자동 도출.
  • 분석만 필요(스캐폴딩 불필요)하면 /cycle-start 없이 unity-pipeline 스킬을 직접 쓸 수 있습니다.
04

9단계 흐름 — 각 단계가 만드는 것

각 단계는 매트릭스(정밀 데이터)와 Mermaid(관계 시각화)를 함께 산출합니다. 게이트(G·)가 걸린 단계는 멈추고 사용자 확인을 받습니다.

단계무엇을산출물게이트
① target기획을 빠짐없이 리스트화(원문↔해석 분리), 분류 트리01_target.mdG1 해석
② goal각 target → 개발 요구사항으로 변환·매핑02_goal.md—
③ scope기구현/신규/변경 판정 + 영향도, 변경범위 시각화03_scope.mdG2 범위
④ assets실제 파일·경로 확정, 추가/수정/삭제/유지 맵, Hierarchy 배치04_assets.mdG3 네이밍
⑤ spec에셋별 기술 명세 + 쉬운 설명 + 산출물 사용 가이드05_spec/<A-ID>_*.md—
⑥ test_env테스트 환경 as-is/to-be + to-be Hierarchy 트리06_test_env.mdG5 적용
⑦ plan구현 task 체크리스트(자동 체크), 작업 큐07_plan.md—
⑧ result결과·diff·검증 증빙·다측면 이점·산출물 인수인계08_result.mdG7 사인오프
⑨ next잔여·후속을 차기 사이클 후보로 이관09_next.mdG8 진행

⑦ 이후: 구현 루프

각 task마다 편집 → (훅이 자동) reserialize·compile·console → play --wait → console 재확인 → 판정. 통과하면 07_plan을 - [x]로 체크하고 다음 task. 이 루프 검증은 test-runner 서브에이전트가 맡아 증빙까지 저장합니다.

06

산출물 읽는 법 — v4의 핵심

산출물 md는 VS Code Foam으로 탐색하는 지식 그래프입니다. 클릭 몇 번으로 관련 문서·용어·실제 파일에 도달합니다.

링크 — 무엇이든 클릭

  • 위키링크 [[2026-06-15_inventory/03_scope]] → 그 문서로 이동. Foam 그래프 뷰로 사이클 전체 연결을 한눈에.
  • ID 앵커 — 매트릭스의 T1·G1·A1·게이트를 클릭하면 정의된 행으로 점프("이 goal이 어느 target에서?").
  • 실제 에셋 링크 — [`Assets/…cs`](…) 클릭 시 진짜 스크립트가 열림(04·08·spec).

Mermaid — 색이 곧 의미

③ scope는 변경 범위를, ④ assets는 추가/수정/삭제/유지를 색으로 보여줍니다. 어느 문서나 같은 5색:

  • 초록 = 추가(new)   골드 = 수정(modify)   빨강 = 삭제
  • 회색 = 유지·기구현(검증만)   파랑 = 흐름·신규 개념

용어 사전 · 증빙 · Hierarchy

요소어디에무엇

모든 문서는 "이 문서는?" 한 단락(왜·무엇·어떻게·언제·누가)으로 시작하고, 어려운 용어엔 풀이를 답니다. 기획·아트 등 누구나 읽는 보고서를 지향합니다.

07

자동화 — 훅과 서브에이전트

반복·검증·게이팅은 자동입니다. 당신은 결정만, Claude는 작업을, 훅은 "항상 일어나야 할 일"을 강제합니다.

Hook (LLM 판단과 무관하게 강제)

  • SessionStart → unity-cli status + 최신 사이클 컨텍스트 주입.
  • PreToolUse → 파괴적 unity-cli 명령을 가로채 승인 요청(G4).
  • PostToolUse → 에셋 편집 후 reserialize → compile → console 자동.
  • Stop → 체크리스트 미완료·색인 미갱신·게이트 미기록 시 종료 차단.

Subagent (기본 위임 — 응답시간·컨텍스트 절약)

에이전트언제 (기본 위임)반환
asset-auditor③ scope 존재성 스캔(질의 3건+)scope 초안 + 사전 등록 후보
spec-writer⑤ spec(에셋 3건+, 병렬)spec md 작성 + 확인 필요점
test-runner구현 루프 · 사인오프 직전 스모크PASS/FAIL + evidence/ 증빙 경로

마감 시 check-links.sh(링크 0 broken)·check-mermaid.sh(다이어그램 0 bad)가 정합을 점검합니다.

전제 — 셋팅이 명시돼야 함

안전선 — 게임 본 코드는 안 고침

플레이 실패 시 테스트 환경·매핑 오류만 자동 수정합니다(씬 배치·더미·경로·참조). Assets/Scripts/의 본 코드 버그가 의심되면 고치지 않고 G6로 보고만 합니다.

09

트러블슈팅

unity-cli 가 offline

Editor가 닫혔거나 Connector 미설치. 분석 단계(①~⑤)는 Editor 없이도 진행되지만, 실행 단계(⑥ 이후)는 Editor를 열어야 합니다. unity-cli status로 ready 확인.

컴포넌트가 플레이 후 사라짐 (missing-script husk)

MonoBehaviour/ScriptableObject는 파일명 = 클래스명 단독 파일이어야 합니다. 한 파일에 여러 클래스를 넣으면 도메인 리로드 한 번에 스크립트 연결이 끊겨 빈 슬롯이 됩니다(실제 회귀로 확인됨 — _conventions §1).

측정이 단일 에디터로 안 됨 (2인 한계)

Steam P2P는 단일 계정 self-connect가 차단되어 2자 측정(RTT 추종·재호스팅 정량·soak)은 2인 실기기가 필요합니다. 단일 에디터로는 host-only 근사까지 — 나머지는 09_next로 인계됩니다.

Stop 훅이 종료를 막음

정상 동작입니다. 미체크 task·색인 미갱신·게이트 미기록이 있다는 뜻 — 07_plan 체크박스, _index.md, decisions.md를 마무리하면 통과합니다.

대용량 출력으로 느림

콘솔 덤프·스냅샷은 stdout으로 받지 말고 파일로(> evidence/…txt, exec 내 File.WriteAllText). exec stdout은 ~6KB에서 잘립니다(쿡북 §9).
