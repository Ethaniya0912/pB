# ⑤ spec — 기술 명세서 (상세)

목적: 각 에셋의 **기술명세**를 에셋 단위 파일로 작성한다. 구현의 직접 근거가 된다.

## 입력
- `04_assets.md` assets 매트릭스(G3 확정본).

## 산출물 — `05_spec/<A-ID>_<에셋명>.md` (에셋당 1파일)
템플릿: `assets/templates/05_spec_asset.md`. 파일명에 A-ID 접두(예: `A1_RnsmHud.md`) —
정렬 보장 + 용어 사전(`glossary/`) 파일명과의 충돌 방지.

## 위임 (기본값 — SKILL §8)
- **에셋 3건 이상이면 `spec-writer` 서브에이전트에 에셋별 병렬 위임**한다(파일을 직접 작성해 옴).
  메인은 반환된 "확인 필요" 지점 검토 + 명세 간 교차 정합(공개 API ↔ 호출 측 기대)만 수행.
- 1~2건이거나 설계 분기가 큰 에셋은 메인이 직접 쓴다.

### 쉬운 설명 섹션 (필수 — 비개발자 독자)
기술 명세 **앞에** "이 에셋이 무엇이고 왜 필요한지"를 1~3문장, 가능하면 비유로 적는다.
어려운 용어는 `[[용어]]` 사전 링크. 예: "RnsmHud 는 계기판(RNSM)을 차에 다는 거치대다."

### 산출물 사용 가이드 섹션 (필수 — _conventions §16)
기술 명세 **뒤에** 만든 뒤 어떻게 쓰는지 4항목: ① 언제·왜 만들어졌나 ② Unity 적용법(§15 배치 유형·
추가 설정) ③ 사용법(켜고 쓰는 실제 절차) ④ 주의점(함정·전제·금지). 코드 모르는 팀원 기준으로 쉽게.

### 스크립트(.cs) 명세 항목
- **클래스명 / 네임스페이스**
- **책임** (1문장, 단일 책임 원칙)
- **공개 API** — 메서드/프로퍼티 시그니처(이름·인자·반환)
- **구현 인터페이스 / 상속**
- **의존성** — 참조 타입·시스템·에셋(A-ID)
- **수명주기** — Awake/Start/Update 등에서의 동작
- **데이터** — 직렬화 필드·ScriptableObject 참조

### 비스크립트(prefab/scene/asset/mat) 명세 항목
- **사양** — 컴포넌트 구성·필드 값·계층(hierarchy)
- **포맷·제약** — 크기/타입/임포트 설정 등
- **참조 관계** — 이 에셋이 참조/피참조하는 대상(A-ID)

## 게이트
- 별도 강제 게이트 없음. 다만 spec 이 ④ 경로·범주와 어긋나면 G3 로 되돌아간다.

## 체크포인트
- 모든 `new` 에셋과 `modify` 에셋(변경점)에 spec 이 있는가?
- 공개 API 가 호출 측(다른 에셋)의 기대와 일치하는가?(상호 참조 검토)

## 흔한 실수
- "어떻게"를 빼고 "무엇"만 적음 → spec 은 구현 지침이므로 시그니처까지 구체화.
- modify 에셋에 전체 명세를 다시 씀 → **변경점 중심**으로 작성.
