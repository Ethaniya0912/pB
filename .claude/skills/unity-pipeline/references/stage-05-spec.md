# ⑤ spec — 기술 명세서 (상세)

목적: 각 에셋의 **기술명세**를 에셋 단위 파일로 작성한다. 구현의 직접 근거가 된다.

## 입력
- `04_assets.md` assets 매트릭스(G3 확정본).

## 산출물 — `05_spec/<asset-slug>.md` (에셋당 1파일)
템플릿: `assets/templates/05_spec_asset.md`.

### 스크립트(.cs) 명세 항목
- **클래스명 / 네임스페이스**
- **책임** (1문장, 단일 책임 원칙)
- **공개 API** — 메서드/프로퍼티 시그니처(이름·인자·반환)
- **구현 인터페이스 / 상속**
- **의존성** — 참조 타입·시스템·에셋(A-ID)
- **수명주기** — Awake/Start/Update 등에서의 동작
- **데이터** — 직렬화 필드·ScriptableObject 참조

### 비스크립트(prefab/scene/asset/mat) 명세 항목
- **사양** — 컴포넌트 구성·필드 값·계층(hierarchy)
- **포맷·제약** — 크기/타입/임포트 설정 등
- **참조 관계** — 이 에셋이 참조/피참조하는 대상(A-ID)

## 게이트
- 별도 강제 게이트 없음. 다만 spec 이 ④ 경로·범주와 어긋나면 G3 로 되돌아간다.

## 체크포인트
- 모든 `new` 에셋과 `modify` 에셋(변경점)에 spec 이 있는가?
- 공개 API 가 호출 측(다른 에셋)의 기대와 일치하는가?(상호 참조 검토)

## 흔한 실수
- "어떻게"를 빼고 "무엇"만 적음 → spec 은 구현 지침이므로 시그니처까지 구체화.
- modify 에셋에 전체 명세를 다시 씀 → **변경점 중심**으로 작성.
