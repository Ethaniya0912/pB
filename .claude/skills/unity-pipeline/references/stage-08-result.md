# ⑧ result — 결과 보고서 (상세)

목적: ①~⑦ 완료 시 결과를 종합하고 as-is→to-be 변화를 스냅샷 diff 로 첨부한다. 사이클을 종료·보관.

## 입력
- 전 단계 산출물 · `decisions.md` · 시작 시 `snapshots/`(as-is) · 종료 시점 스냅샷(to-be).

## 활동 체크포인트
1. **요약** — 무엇을 했는가(1문단). 비개발자도 읽을 수 있게 평문으로.
2. **달성 대비표** — target/goal 대비 완료 여부(미완료·보류 항목 명시).
3. **as-is→to-be diff** — 시작 스냅샷과 종료 스냅샷을 비교(추가/변경 에셋 목록).
   - 종료 스냅샷: 쿡북 §7 덤프를 `snapshots/<ts>_after.json` 로 저장 후 diff.
   - 에셋 경로는 **클릭 링크**로(`_conventions.md` §9) — 보고서에서 바로 결과물이 열린다.
4. **검증 증빙 작성** (`_conventions.md` §10 · 쿡북 §8) — "검증 완료"의 근거 첨부:
   a. 검증 **시작/종료 시각**을 기록한다(루프 시작 전 `date`, 종료 후 `date`).
   b. `unity-cli status` 출력(Unity·Connector 버전)을 **검증 환경** 표에 기입.
   c. **task별 검증 기록** 표 — A-ID·시각·방법(compile/play/console/수동)·판정·근거 링크.
   d. 판정 근거 콘솔 출력을 `evidence/console_*.txt` 로 저장하고 핵심만 ```log 발췌.
   e. 플레이 검증 화면(HUD 등)을 `evidence/*.png` 로 캡처해 임베드(쿡북 §8 스크린샷).
   f. 수동 검증 항목은 "수동 — 절차서 링크·수행자·일시" 형식으로 기록.
5. **다측면 이점 정리**(_conventions §14) — 이번 사이클이 가져온 가치를 측면별 표로:
   **게임(플레이어 체감)·개발(생산성·안정성)·기획(검증·의사결정)·아트(작업 기반)·운영(측정·이력)**.
   해당 없는 측면은 "해당 없음"으로 남겨 누락과 구분한다. 추상적 미사여구 금지 — 구체적 사실 기반.
6. **잔여 이슈 / 후속 사이클 제안** — 실행 가능한 이관 후보는 ⑨ next 로 구조화(여기선 요약).
7. **게이트 결정 요약** — `decisions.md` 핵심을 인용·링크.
8. **용어 사전 갱신 내역** — 이번 사이클 등록/갱신 용어 나열(⑦ plan 마감 정리와 대응).
- **Mermaid**: 달성 요약(`flowchart` G→달성) 또는 이점(`mindmap`)을 매트릭스와 함께 둔다(§13).
- "달성 대비표"의 target/goal 은 `[T1](01_target.md#T1)`·`[G1](02_goal.md#G1)` 로 점프(§7-A).

## 산출물 — `08_result.md`
섹션: 요약 · 달성 대비표 · diff · **검증 증빙(환경/시각·task별 기록·콘솔 발췌·스크린샷·산출물)** ·
**다측면 이점** · 잔여 이슈 · 게이트 결정 요약 · 용어 사전 갱신.

## G7 게이트 (Stop 강제)
- 보고서·diff·증빙·이점 을 사용자에게 검토받고 **사인오프**한다.
- 사인오프 후:
  - `meta.json.status="signed_off"`, `awaiting_gate` 제거.
  - `_index.md` 에 완료 행 append.
  - **→ ⑨ next 로 진행**(이관 정리 + G8 질의). archive 이동은 ⑨ 의 G8 결정(종료) 후로 미룬다.
- 양식·기록: `references/gates.md`.

## 종료 후 (사용자 수동)
- git 커밋/PR(사용자). 결정 로그(`decisions.md`)는 이후 사이클의 컨텍스트가 된다.
- ⑨ next 의 G8 에서 "다음 사이클 바로 진행"을 선택하면 연속으로 새 사이클이 시작된다.

## 흔한 실수
- diff 없이 "완료"만 보고 → 반드시 스냅샷 비교를 첨부.
- 미완료 task 를 숨김 → Stop 훅이 차단하며, 보고서에 잔여로 명시해야 함.
- "검증 완료"만 적고 증빙 없음 → 시각·환경·콘솔·스크린샷이 빠진 검증은 재현 불가.
  evidence/ 가 비어 있으면 ⑦ plan "마감 정리" task 를 체크할 수 없다.
- 증빙 원문을 md 본문에 통짜로 붙임 → 발췌+링크(파일은 evidence/)로 분리.
