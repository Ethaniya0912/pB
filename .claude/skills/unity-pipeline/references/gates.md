# 게이트 규약 (G1~G7) — 질문 양식 · decisions.md 기록 형식

> R2(휴먼-인-더-루프)의 구현. 게이트에 도달하면 **자동 진행을 멈추고** 아래 양식으로 질문한다.
> 핵심 게이트는 훅이 강제한다(Stop/PreToolUse). 모든 결정은 `decisions.md` 에 기록한다.

## 게이트 요약
| 게이트 | 시점 | 강제 | 무엇을 확인 |
|---|---|---|---|
| G1 | ① 직후 | Stop | 기획 해석·모호/누락 항목 |
| G2 | ③ 직후 | Stop | 변경 범위·영향도(기존 에셋 수정) |
| G3 | ④ 직후 | Stop | 파일·경로명 확정 |
| G4 | 파괴적 CLI 직전 | PreToolUse | 덮어쓰기/삭제·대량 변경 |
| G5 | ⑥ 직후 | Stop | as-is→to-be 적용 |
| G6 | 테스트 실패 시 | 수동 | 설계 분기 결정 |
| G7 | ⑧ 직전 | Stop | 최종 사인오프 |

## "멈추고 질문" 행동 규칙
1. 단계 산출물을 요약한다(매트릭스 핵심 행 + 결정이 필요한 지점).
2. **선택지를 제시**한다(예: 승인 / 수정안 A / 수정안 B). 비복구·고영향이면 임의 진행 금지.
3. 사용자 응답을 받기 전에는 다음 단계로 넘어가지 않는다.
4. 응답을 `decisions.md` 에 기록하고, 필요하면 산출물·`meta.json` 을 갱신한다.

## 질문 양식 (예: G2)
```
[G2 · 변경 범위·영향도 승인] 사이클: 2026-06-11_inventory
요약:
  - 신규 3건 (InventorySystem, ItemDatabase, InventoryUI)
  - 기존 변경 1건: PlayerController (Inventory 참조 추가) — 영향: Player.prefab, Main.unity
질문:
  1) PlayerController 변경을 승인하시겠습니까?
  2) 영향 씬(Main.unity)도 이번 사이클 범위에 포함할까요?
선택지: [승인 / 변경 제외 / 다른 범위로 수정]
```

## decisions.md 기록 형식
```
## G2 (2026-06-11 14:30) — 승인
- 결정: PlayerController 변경 승인, Main.unity 포함
- 사유: 인벤토리 진입점이 Player 이므로 불가피
- 후속: 04_assets 에 A7(Main.unity, modify) 추가
```
- 헤더에 **게이트 ID(G2)** 를 반드시 포함한다 → Stop 훅이 `awaiting_gate` 와 대조해 기록 여부를 검사한다.

## 게이트별 포인트
- **G1**: 원문↔해석 분리가 됐는가? 모호도 "높음" 항목을 빠짐없이 질문했는가?
- **G2**: 기존 에셋 변경·중복 구현 후보를 정확히 짚었는가? 이전 사이클 재사용을 반영했는가?
- **G3**: 경로/네이밍이 `_conventions.md` 규약과 일치하는가? 확정 후 변경은 비용이 큼.
- **G4**: 가드가 ask/deny 를 띄움 → 사용자에게 **무엇이 왜 위험한지** 한 줄로 설명하고 대안을 제시.
- **G5**: to-be 가 unity-cli 로 재현 가능한 수준으로 구체적인가? 적용 범위를 확인.
- **G6**: 실패가 기계적 버그가 아니라 설계 선택이면, 트레이드오프와 함께 2~3개 선택지를 제시.
- **G7**: 08_result 의 diff 가 실제 변경과 일치하는가? `_index.md` 완료 기록·archive 이동 합의.
