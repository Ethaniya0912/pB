# ① target — 기획 내용 정리 (상세)

목적: 기획 문서의 **순수 기획 내용**을 빈틈 없이 리스트화·분류하고, 해석과 원문을 분리한다.

## 입력
- `00_input/` 의 기획·구현·기술개론 문서.
- as-is 스냅샷(`snapshots/`) — `/cycle-start` 가 생성.

## 활동 체크포인트
1. 문서를 통독하고 **기획 단위**(기능/시스템/콘텐츠/UX/제약)로 쪼갠다.
2. 각 항목을 target 매트릭스 1행으로 기록한다. **원문근거**(인용)와 **해석**(SE 관점)을 분리.
3. 누락·모순·모호 지점을 표시한다(모호도 "높음").
4. 암묵 요구(성능·플랫폼·기존 시스템 제약)를 명시적 항목으로 끌어올린다.

## 산출물 — target 매트릭스
컬럼: `T-ID | 항목 | 분류 | 원문근거 | 해석 | 모호도` (스키마: `matrix-schemas.md`)

예시:
| T-ID | 항목 | 분류 | 원문근거 | 해석 | 모호도 |
|---|---|---|---|---|---|
| T1 | 슬롯 기반 인벤토리 | 시스템 | "20칸 가방" p.3 | 고정 20슬롯 그리드 | 낮음 |
| T2 | 아이템 스택 | 기능 | "겹침 가능" | 최대 스택 수 미정 | 높음 |

## G1 게이트 (Stop 강제)
- 모호도 "높음" 항목 + SE 해석을 사용자에게 확인받는다.
- 질문 양식: `references/gates.md` §질문 양식. 결정은 `decisions.md` 에 `## G1 ...` 로 기록.
- 통과 후 `meta.json.status="planning"`, `awaiting_gate` 해제.

## 흔한 실수
- 해석을 원문처럼 적기 → 반드시 분리.
- "당연한" 제약 누락(타깃 플랫폼·기존 세이브 호환 등).
