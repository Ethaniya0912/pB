# ⑨ next — 다음 사이클 이관 (상세)

목적: 이번 사이클에서 다 못 했거나 새로 발견해 **다음으로 넘길 것**을 차기 `/cycle-start` 의 입력이
되도록 구조화하고, 다음 사이클 즉시 진행 여부를 사용자에게 질의한다(G8).

## 입력
- `08_result.md`(잔여 이슈·후속 제안·다측면 이점) · `decisions.md`(미결 분기) · 측정 대기 항목.

## 활동 체크포인트
1. result 의 "잔여 이슈 / 후속 제안"을 **실행 가능한 차기 후보**로 승격한다(막연한 제안 금지).
2. 각 후보를 분류: **이월**(이번에 시작했으나 미완) · **신규**(이번에 발견된 새 작업) · **측정**(2인/실기기 등 대기).
3. 출처를 이번 사이클 산출 지점으로 링크한다(`[⑧ 잔여](08_result.md)` 등 §7-A).
4. **권장 다음 사이클**을 제안한다: slug·입력 문서·선행 조건(예: "2인 측정 선행 필요").
5. 이관 흐름을 Mermaid(`flowchart LR`, 이번 산출 → 차기 후보)로 그린다.
6. 이관할 게 없으면 **"이관 없음"** 을 명시하고 사이클을 종결한다(빈 문서 금지).

## 산출물 — `09_next.md`
- 차기 후보 매트릭스: `차기후보 | 유형(이월/신규/측정) | 출처 | 우선순위 | 비고`
- 이관 Mermaid + 권장 다음 사이클(slug·입력·선행조건).

## G8 게이트 (다음 사이클 진행 질의 — 수동)
문서 끝에서 **자동 진행을 멈추고** 사용자에게 묻는다:
```
[G8 · 다음 사이클] 사이클 <id> 종료. 09_next 의 우선 후보:
  - N1 (…) — 유형/우선순위
질문: 다음 사이클을 바로 시작할까요?
선택지: [예 → /cycle-start <권장입력> <slug> / 아니오 → 인계장 보관 후 종료 / 다른 후보·범위로 조정]
```
- **예** → 권장 입력으로 `/cycle-start` 를 안내·실행(연속 진행).
- **아니오** → `09_next.md` 를 인계장으로 보관하고 종료. 다음 세션이 이 문서로 재개한다.
- 결정을 `decisions.md` 에 `## <a id="G8"></a>G8 …` 로 기록.

## 흔한 실수
- 잔여를 막연히 나열만 함 → "다음 사이클이 바로 집어들 수 있는" 입력 형태(slug·범위·선행조건)로.
- 이관 없는데 빈 문서로 남김 → "이관 없음 — 이 기능 라인 종결" 처럼 명시.
- G8 질의를 건너뛰고 임의 진행 → 다음 사이클 시작은 반드시 사용자 결정.
