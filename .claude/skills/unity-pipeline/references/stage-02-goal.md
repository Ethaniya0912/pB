# ② goal — 개발 요구사항 도출 (상세)

목적: 각 target 을 **구현 가능한 개발 요구사항**으로 변환하고 매핑한다.

## 입력
- `01_target.md` 의 target 매트릭스(G1 승인본).

## 활동 체크포인트
1. 각 T-ID 를 1개 이상의 개발 요구사항으로 변환한다(1:N 가능).
2. 요구사항별 **필요 시스템**과 **에셋 범주**(`_conventions.md` §2)를 분류한다.
3. 우선순위(P0/P1/P2)를 부여한다 — P0=핵심 동작, P2=후순위.
4. target↔goal 매핑이 빠짐없는지 역방향으로 점검(모든 T-ID 가 최소 1 goal 에 연결).

## 산출물 — goal 매트릭스
컬럼: `G-ID | 연결 target | 개발 요구사항 | 필요 시스템 | 에셋 범주 | 우선순위`

예시:
| G-ID | 연결 target | 개발 요구사항 | 필요 시스템 | 에셋 범주 | 우선순위 |
|---|---|---|---|---|---|
| G1 | T1 | 20슬롯 인벤토리 데이터/UI | Inventory | Script, Prefab, UI | P0 |
| G2 | T2 | 스택 병합 로직 | Inventory | Script | P1 |

## 게이트
- 별도 강제 게이트 없음. 단, target 매핑 누락이 보이면 G1 로 되돌아가 확인한다.

## 흔한 실수
- 요구사항이 "무엇"이 아니라 "어떻게"로 흐름 → 구현 방식은 ⑤ spec 에서.
- 한 goal 에 너무 많은 책임 → 구현/테스트 단위가 커진다. 적절히 분할.
