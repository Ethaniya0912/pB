# test_run · 에셋 매핑 — <cycle-id>

> **이 문서는?** 테스트 씬의 각 **에셋 슬롯**에 무엇을 채울지(더미 stub / 실제 에셋) 지정·추적하는
> 매핑표입니다(무엇). 같은 테스트를 더미로도, 실제 에셋으로도 반복하려고(왜) 슬롯별 현재 상태와 실제
> 경로를 적어 `/test-run` 재실행이 이 표를 읽게 하며(어떻게), 사용자가 더미↔실제를 바꿀 때 편집합니다(언제·누가).
> 규약: [[_conventions#17-D. 더미 ↔ 실제 교체 (결정: 둘 다 지원)|_conventions §17-D]].

## 매핑표
> `현재` 를 `실제` 로 바꾸고 `실제 경로` 를 채운 뒤 `/test-run <cycle-id>` 재실행 → 실제 에셋으로 테스트.
> 또는 `Assets/_TestRuns/<cycle-id>/assets/` 의 같은 경로에 실제 파일을 드롭하면 재실행 시 자동 인식(이 표도 갱신).

| 슬롯 | 범주 | 테스트 경로 (Assets/_TestRuns/<cycle-id>/assets/…) | 현재 | 실제 에셋 경로(교체용) | 비고 |
|---|---|---|---|---|---|
| S1 | Prefab | `Prefabs/<…>.prefab` | 더미 |  | 동작 stub: <컴포넌트·메시·머티리얼> |

## 교체 방법 (둘 다 지원)
1. **매핑 매니페스트** — 위 표에서 `현재=실제` + `실제 에셋 경로` 기입 → 재실행. 실제 경로의 에셋을
   테스트 경로로 복사/링크해 사용. (실제 경로가 비면 더미 유지.)
2. **폴더 드롭** — `Assets/_TestRuns/<cycle-id>/assets/` 에 더미와 **같은 상대경로·이름**으로 실제 에셋을 넣으면
   재실행이 더미를 덮지 않고 실제를 사용. 더미는 이름 마커(`__DUMMY`)로 구분되므로 충돌 없음.
