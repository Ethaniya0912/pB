## 1. 재구성 원칙 — "측정 없이는 수정 없다"
v1.1의 단계 진행은 모든 Step에서 동일한 4박자를 따른다:

```
① Baseline (Step 0에서 기록된 수정 전 측정치)
② Fix      (해당 Step 구현)
③ Re-measure (동일 SCN 시나리오·동일 네트워크 프로파일로 재측정)
④ Gate 판정 (Before/After 표 작성 → Reports\StepN_Evidence.md 누적)
```

| 단계 | 명칭 | 포함 이슈 | 게이트 |
|---|---|---|---|
| **Step 0** | **계측 기반 구축 (신설)** | P2-7(전반), P2-4(채널화), 베이스라인 측정 | 모든 Step의 선행 |
| Step 1 | 전송 안정화 | P0-1, P0-2, P0-4, P1-2, P1-1, (P2-8 최소가드) | 데모 필수 선행 |
| Step 2 | 권위 일원화 | P0-3, P0-5+P1-10(묶음), P1-3, P1-4, P1-9, P1-11 | 데모 필수 |
| Step 3 | 규약 표준화 | P1-7, P1-12, P2-5, P2-6, P2-10, P1-8, **P1-6(복귀)** | 데모~EA |
| Step 4 | 효율화 | P2-1, P2-2(처방 교정), P2-3, P2-9, P1-5 | EA |
| Step 5 | 검증 고도화·잔여 동기화 | P2-7(자동화 고도화), P2-11, P2-12, P2-8(전면) | EA + 상시 |

## 2. 표준 시나리오 (SCN) — 전 단계 공통 측정 단위
모든 측정은 아래 시나리오 ID + 네트워크 프로파일 조합으로 수행하고, 결과 파일명에 `SCN-XX_PROF-X_StepN_before|after`를 명기한다.

**네트워크 프로파일** (NGO Network Simulator 또는 Clumsy):
- `PROF-G`(Good): RTT 30ms, 손실 0%
- `PROF-A`(Avg): RTT 150ms, 손실 2%, 지터 ±30ms
- `PROF-B`(Bad): RTT 250ms, 손실 5%, 지터 ±60ms

| ID | 시나리오 | 절차 요약 | 주 측정 지표 |
|---|---|---|---|
| SCN-01 | 접속·초기 동기화 | 호스트 월드 생성 → 클라 접속(인벤 100+ 항목 사전 적재) | 접속 성공률, 초기 스냅샷 무손상, M2 |
| SCN-02 | 끊김·재호스팅 | 클라 Alt+F4 ×5 → 호스트 방 파기·재생성 ×10 | M3, M8, 유령 클라 수 |
| SCN-03 | 전투 50회 | 2인 상호 패링/회피/타격 각 50회 (PROF-A 고정) | M5 판정 일치율, 예외 0 |

## Step 0 · 계측 기반 구축 (신설 — 최우선)
> **목표**: 이후 모든 단계의 효과를 숫자로 입증할 수단을 먼저 확보하고, 수정 전 베이스라인을 기록한다. **게임 로직은 일절 수정하지 않는다**(P2-4의 로그 채널화만 예외 — 이는 계측 도구의 일부).
> **소요 특성**: 대부분 패키지 도입·래퍼 작성·절차 문서화. 코드 침습 최소.
### 0.A 상세 진행계획
#### 0.A.1 — 패키지·외부 도구 도입
1. **Unity Multiplayer Tools** (`com.unity.multiplayer.tools`) 설치:
   - **RNSM(Runtime Net Stats Monitor)**: RTT·송수신 바이트·이벤트의 인게임 HUD. P2-7 HUD 요구의 80%를 무비용 충족.
   - **Network Profiler**: 오브젝트별·변수별 대역폭 분해 → M6·M7의 측정기.
2. **Network Simulator**(동 패키지) 또는 Clumsy로 PROF-G/A/B 프로파일 3종을 프리셋화.
3. 주의: RNSM의 RTT는 Transport `GetCurrentRtt` 기반 → **현행 0 표시가 정상이며, 그 0이 곧 M1 베이스라인 증거**다.
#### 0.A.2 — 계측 래퍼 3종 작성 (신규 코드, 게임 로직 무침습)
1. **NetEventLogger**: `OnClientConnectedCallback`/`OnClientDisconnectCallback`/Transport 이벤트를 타임스탬프 기록 → M3·M8. *P0-2 검증의 핵심 도구.*
2. **VerdictLogger**: 전투 판정 이벤트(히트·패링·블록·데미지값)를 양측 머신에서 `{serverTime, attacker, victim, verdict}` CSV로 기록 → 세션 후 diff로 M5 산출. *Step 2 효과 입증의 핵심 도구.*
3. **StateChecksum v0**: 8바이트 해시 보고 RPC 골격 — 지형 paramHash + 인벤 목록 해시를 30초 주기 서버 비교, 불일치 시 LogError. (EnvFlagRegistry 설계서 §5 Step 7의 선행 구현. 8B RPC이므로 P0-1 버퍼 1KB 제약과 무관하게 지금 도입 가능)
4. **P2-4 채널화**: Transport의 패킷당 `Debug.Log`를 `#if NETCODE_DEBUG` + 카운터 집계로 전환 → 로그가 '소음'에서 M9 '계측기'로 바뀜.
#### 0.A.3 — 측정 절차 표준화
1. §2 SCN-01~07 절차서를 `Reports\SCN_Procedures.md`로 고정(조작 순서·소요 시간·기록 양식).
2. **soak 하네스 v0**: 30분 타이머 + NetEventLogger/체크섬 로그 자동 수집 + 종료 시 요약 md 생성(완전 자동화는 Step 5, 여기서는 수집 자동화까지).
3. 강제 끊김 매크로(클라 프로세스 kill 스크립트) 작성 → SCN-02 반복의 인적 비용 제거.
#### 0.A.4 — 베이스라인 측정 집행
- SCN-01~07 전체를 PROF-G/A에서 1회씩 수행, §3 표의 M1~M11 실측치 기록 → `Reports\Step0_Baseline.md`.
- **알려진 P0 결함 하에서의 측정임을 명기**: P0-2 때문에 끊김 지표는 왜곡된 형태로 기록됨(그 왜곡 자체가 증거), P0-5 때문에 SCN-04 클라 줍기는 0%로 기록될 것.
- SCN-01에서 접속 실패가 재현되면(P0-1) 인벤 항목 수를 이등분 탐색해 **실패 임계 크기**를 기록 — Step 1 After와 대비할 가장 선명한 증거.

- 요리 4종 NetworkVariable → 상태 Enum + 시작 서버시각만 동기화, 진행도는 결정 함수 로컬 재계산. **EnvFlagRegistry 시계형 플래그의 예행연습**(설계서 도입 차수 1과 동일 작업 — 중복 수행 아님을 양 문서에 상호 명기).
#### 4.A.3 — P2-2 아이템 보간 (R3 교정판)
- 현행 `Lerp(cur, target, Time.deltaTime*speed)`는 프레임률 의존 지수 감쇠 — **수정**: ① 스폰 시 netPosition 즉시 스냅 ② OnValueChanged 기반 보간 목표 갱신 ③ 보간식을 프레임률 독립으로 교체(`1-Mathf.Exp(-k*Time.deltaTime)` 보정 또는 `MoveTowards` 고정 속도) ④ 일정 거리 초과 시 텔레포트 스냅 ⑤ 제자리 회전 동기 추가(회전 단독 변경도 송신).
#### 4.A.4 — P2-9 잡기 시각 상태
- 손 부착 대상을 `NetworkVariable<ulong>`(잡은 캐릭터 ID)로 승격 → 난입 동시 해결(M10 잡기 항목).
#### 4.A.5 — P1-5 WeaponItem SO 누수
- DB 원본 참조 + 런타임 스탯 분리(근본). 임시: 교체 시 이전 인스턴스 Destroy. (Step 4 유지 근거: 권위·동기화와 무관한 메모리 이슈 — R4)
